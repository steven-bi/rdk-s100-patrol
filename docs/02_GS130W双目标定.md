# GS130W 左右目确认、双目标定与测距核验

## 1. 为什么不能直接填写左右目

当前输入 `/image_combine_jpeg` 是一个组合画面，默认配置为上下拼接、每半幅再逆时针旋转 90°，检测主视图暂定为组合图下半幅。`top`/`bottom` 只描述数据位置，不等于物理左/右镜头。

物理左右目写反会产生错误视差。系统宁可显示“距离：不可用”，也不能用猜测方向生成错误距离。因此必须先做遮挡实验。

## 2. 遮挡法确认物理左右目

在带桌面显示的板端终端：

```bash
cd /opt/rdk-patrol/current
source /opt/tros/humble/setup.bash
python3 scripts/tools/collect_gs130w_pairs.py \
  --mode inspect \
  --topic /image_combine_jpeg \
  --layout vertical \
  --rotation ccw90 \
  --output /var/lib/rdk-patrol/calibration/occlusion
```

操作：

1. 固定相机，确保两个镜头均有画面。
2. 用不透光物体**完全遮住物理左镜头**，不要碰动支架。
3. 观察程序标为 `TOP` 还是 `BOTTOM` 的画面变黑，按 `s` 保存快照。
4. 移开遮挡，再完全遮住物理右镜头，重复观察和保存。
5. 记录结论，例如“物理左目=`top`，物理右目=`bottom`”。
6. 重新启动相机驱动后再抽查一次，确认驱动不会交换顺序。

如果板端无桌面，可先用 `ros2 bag` 录制组合话题，在有显示环境的同架构机器回放后执行；不能仅凭画面透视猜左右。

也可在纯 SSH 环境自动保存遮挡序列：

```bash
python3 scripts/tools/collect_gs130w_pairs.py \
  --mode inspect \
  --headless \
  --count 12 \
  --auto-interval 2 \
  --output /var/lib/rdk-patrol/calibration/occlusion
```

运行期间依次保持“不遮挡、遮物理左目、不遮挡、遮物理右目”，每种状态至少维持 6 秒。完成后把保存的 `top/bottom` 图片拉回查看。

## 3. 标定板

建议使用：

- 9×6 个**内角点**的平面棋盘格。
- 单格边长 25–40 mm，按实际测量值填写。
- 硬质平板，平整、哑光、无翘曲。
- 打印后用钢尺或游标卡尺复测多个格子；不要使用打印对话框的“适合页面”缩放。

命令中的 `--board-cols 9 --board-rows 6` 指内角点数，不是黑白方格总数。`--square-size-mm` 必须填实测单格尺寸。

可生成 9×6 内角点、30 mm 单格的精确 SVG：

```bash
python3 scripts/tools/generate_chessboard.py \
  --inner-cols 9 \
  --inner-rows 6 \
  --square-mm 30 \
  --margin-mm 20 \
  --output /var/lib/rdk-patrol/calibration/chessboard_9x6_30mm.svg
```

此尺寸含白边约 340×250 mm，应使用 A3 或更大纸张。打印后按同目录“打印说明”复测，并用实测平均单格边长替代名义 30 mm。

## 4. 采集同步图像对

正式标定推荐使用浏览器手动采集工具，不再使用定时自动保存。旧工具的
`--auto-interval` 只是两次保存之间的最短间隔，启动后第一组仍可能立即保存，
也不会判断运动、旧帧或重复姿态，因此只保留作诊断回退。

本机当前已经通过遮挡实验确认：

- 物理左目=`bottom`
- 物理右目=`top`
- 运行旋转=`ccw90`

更换摄像头或驱动后不能沿用此结论。

### 4.1 一次性安装手动工具

在 Windows 双击：

```text
scripts\windows\安装GS130W手动采集工具.cmd
```

依提示输入板端密码和 `sudo` 密码。最后必须看到：

```text
WEB_COLLECTOR_READY
```

### 4.2 启动网页手动采集

先确认：

1. 摄像头固定，整个采集期间绝不移动。
2. 棋盘粘在完全平整、不会弯曲的哑光硬板上。
3. 不要预先创建、清空或复用板端输出目录。

然后在 Windows 双击：

```text
scripts\windows\启动GS130W手动采集.cmd
```

脚本只停止融合检测服务，不停止 GS130W/ROS 相机节点，并建立仅本机可访问的
SSH 隧道。看到“手动采集网页已启动”后打开：

```text
http://127.0.0.1:8765/
```

网页显示物理左右目实时画面、采集计数和九宫格位置覆盖。只有以下条件全部通过，
“采集本组”按钮才会变绿：

1. 左右目均完整识别 9×6 内角点。
2. 摄像头画面持续产生新帧，不是断流后的旧图。
3. 棋盘连续至少 1.2 秒、至少 3 个新帧保持稳定。
4. 棋盘足够大，估算的全部外边缘均在左右目画面内。
5. 与所有已保存组相比，位置、距离、旋转或透视角度至少一项明显不同。

工具任何时候都不会自行保存。点击按钮后，主循环会等待下一张同步新帧再次复核；
2 秒内连新帧都没有到达就取消请求，绝不会稍后突然误采。及时到达的新帧即使角点
计算稍慢也会完成复核；不合格仍不保存。双击按钮也只接受一次请求。

### 4.3 每一组的实际操作

1. 将棋盘移出画面。
2. 按下表摆到新位置，只移动棋盘，不移动相机。
3. 查看左右目预览，确保整张棋盘外边缘均可见并留有背景。
4. 完全停止移动，等待五项状态全部变绿。
5. 点击一次“采集本组”。
6. 明确看到“已保存第 N/30 组”后，再把棋盘移出画面。

建议 30 组分配：

- 1–3：画面中心，近、中、远。
- 4–7：左上、右上、左下、右下。
- 8–11：上、下、左、右边缘，外框不能出画。
- 12–17：下半画面的左、中、右，各两个距离。
- 18–21：向左、向右、向上、向下倾斜约 15°–25°。
- 22–25：四角位置加轻微俯仰或偏航。
- 26–28：较远的中心、下左、下右；棋盘宽度仍不小于画面约五分之一。
- 29–30：较近的左、右位置，仍须保留完整外边缘。

同一九宫格位置允许通过改变距离或倾斜角形成不同姿态。网页负责阻止近似重复，
但不能替代上述人工覆盖规划。

### 4.4 结束、暂停和恢复服务

- 达到 `30/30` 后工具自动结束。
- 需要暂停时点击网页“安全结束/稍后继续”；完整图像对会保留，下次启动脚本会
  复检并从现有编号继续。
- 仅关闭浏览器页面不会停止板端工具。
- Windows 脚本退出时会自动恢复并核验 `rdk-patrol.service`，必须看到
  `RDK_PATROL_ACTIVE`。
- 若采集写盘瞬间断电，工具可能检测到半组文件并拒绝恢复。这是防止污染标定数据的
  安全行为；不要自行删除，保留目录并按现场记录另建重试目录。

输出目录固定为：

```text
/var/lib/rdk-patrol/calibration/gs130w_pairs_20260729_v2
```

工具发现未知文件、左右图不完整、编号不连续或可能覆盖旧文件时会直接拒绝启动。
完成后先把三类文件拉回电脑并离线审计；不要直接执行标定。

## 5. 计算标定

先保持 `valid:false` 生成结果：

```bash
python3 scripts/tools/calibrate_gs130w.py \
  --pairs /var/lib/rdk-patrol/calibration/gs130w_pairs_20260729_v2 \
  --board-cols 9 \
  --board-rows 6 \
  --square-size-mm 30.0 \
  --physical-left-view bottom \
  --layout vertical \
  --runtime-rotation ccw90 \
  --output /var/lib/rdk-patrol/site-config/stereo_gs130w.yaml
```

基本通过线：

- 双目 RMS 不大于 1.0 px。
- 中位极线误差不大于 1.0 px。
- 基线长度为合理正数，并与相机物理规格大致一致。
- 使用的有效同步图像不少于 12 对，建议不少于 20 对。

若指标不通过，重新采集比放宽阈值更安全。`--accept` 只适合实验室明确完成全部核验后的受控场景；生产流程应继续执行已知距离验证，由核验工具最终把 `valid` 设为 `true`。

## 6. 已知距离核验

旧版 `check_stereo_distance.py --record-result` 不再用于生产启用：它的筛选条件与正式运行时不完全一致，而且失败重试可能污染 working YAML。

请改用新的固定三槽网页验证器，完整直接操作见：

```text
docs\08_GS130W三点距离验证_直接操作.md
```

Windows 入口：

```text
scripts\windows\启动GS130W三点测距验证助手.cmd
```

新流程固定为 `1m → 3m → 5m`，每个距离自动采集 3 个点击后的新同步帧，在最清晰的校正左目图上只框一次 ROI，并用同一 ROI 严格评估三帧。它复用正式运行时的灰度 `SGBM_3WAY`、有效视差、`Z>0`、ROI 边界腐蚀和 10%–90% 距离裁剪，并增加更严格的有效率、MAD、分布和三帧一致性门槛。

候选文件始终保持 `valid:false` 且字节不变。只有三个固定槽全部通过，工具才在独立会话目录另建新的 `valid:true` YAML；完成后先人工复核审计包，不会自动覆盖生产配置。生产安装必须使用单独的严格审核安装器，并在人工确认后执行。

## 7. 运行时验收

使用安全、可控的明火样本或经审核的回放素材，验证：

- `fire` 连续约 2 秒后触发，`smoke` 不触发。
- 有效视差时关键帧显示距离，数值与实测误差在现场验收范围内。
- 遮挡一目、低纹理、过曝或视差不足时仍产生明火报警，关键帧明确显示“距离：不可用”。
- 明火持续存在时每 10 分钟复报一次。
- 估距计算只针对明火候选区域，不拖低完整链路至 15 FPS 以下。

## 8. 何时必须重新标定

出现下列任一情况必须重新做遮挡确认、标定和已知距离核验：

- 更换 GS130W 或相机序列号变化。
- 两镜头相对位置、焦距、分辨率或驱动输出顺序改变。
- 相机支架受到撞击、拆装或明显位移。
- 运行时旋转、组合布局或图像裁剪改变。
- 已知距离抽检超差。

旧标定文件应随拉回包归档，但不能继续用于已改变的硬件。
