# RDK S100 部署与预检

## 1. 板端和网络准备

生产部署前准备：

- RDK S100 与 GS130W 双目相机，板端系统和相机 ROS 2 驱动可正常启动。
- 板端 Python 3.9 或更高版本；RDK 系统镜像自带的 BPU/HBM 运行时必须与模型兼容。
- ROS 2 话题 `/image_combine_jpeg` 可见，消息类型为 `sensor_msgs/msg/CompressedImage` 或 `sensor_msgs/msg/Image`。
- Windows 运维电脑与板端位于可信局域网，能访问 SSH 22 端口和巡检只读网页 8081 端口；8080 保留给相机网页。
- 至少 512 GB 高耐久存储用于双路 72 小时录像；运行数据目录建议挂载到该盘。
- 板端账号默认 `sunrise`，具备 `sudo` 权限，并有相机、BPU 和 ROS 2 所需设备权限。

不要先复制 MiniMax Key 到项目文件。密钥只放在板端 `/etc/rdk-patrol.env`。

## 2. 首次板端预检

先登录板端：

```bash
ssh sunrise@192.168.66.65
```

检查时间和时区：

```bash
timedatectl
sudo timedatectl set-timezone Asia/Shanghai
sudo timedatectl set-ntp true
```

加载板端 ROS 2 环境后检查相机：

```bash
source /opt/tros/humble/setup.bash
ros2 topic list
ros2 topic type /image_combine_jpeg
ros2 topic hz /image_combine_jpeg
```

如果板端实际 setup 文件不同，可检查 `/opt/tros/setup.bash` 或 `/opt/ros/humble/setup.bash`。相机输入不稳定达到 15 FPS 时，融合程序不可能凭空达到 15 FPS，应先修复驱动、USB/网口或曝光设置。

确认数据盘：

```bash
lsblk -f
df -h
```

如果把外置盘挂载为 `/var/lib/rdk-patrol`，必须写入 `/etc/fstab` 并验证重启后仍自动挂载。不要在未挂载时启动 72 小时录像，否则会写满系统盘。

## 3. Windows 一键部署

在交付目录双击 `scripts\windows\部署到RDK.cmd`。默认连接：

```text
sunrise@192.168.66.65:22
```

需要修改地址或用户名时，在 PowerShell 运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\Deploy-RdkPatrol.ps1 `
  -BoardHost 192.168.66.80 `
  -User sunrise `
  -SshPort 22 `
  -RemotePrefix /opt/rdk-patrol `
  -RemoteDataDir /var/lib/rdk-patrol
```

自定义程序/数据目录必须是至少两级、名称含 `rdk` 或 `patrol` 的应用专用绝对目录，不能位于 `/etc`、`/usr`、`/home`、`/tmp` 等系统关键目录；`/var` 下只允许 `/var/lib/<应用目录>`。两个目录不能相同，也不能互为父子目录。默认值符合这些安全规则。

脚本执行以下操作：

1. 本地打包项目和 HBM 模型，不包含 `.git`、虚拟环境、缓存和运行数据。
2. 上传到板端 `/tmp` 暂存目录。
3. 创建一个新的 `/opt/rdk-patrol/releases/<时间戳>`。
4. 建立使用系统板端库的 Python 虚拟环境并安装本项目。
5. 保留 `/var/lib/rdk-patrol/site-config` 中已有业务参数、标定和点位登记。
6. 原子切换 `current` 符号链接，安装并启动 systemd 服务。
7. 执行预检。

安装不会删除旧 release、录像或报警。若安装失败，上传包和板端暂存目录也会保留，便于排查。

### 离线 Python 依赖

RDK 镜像通常已经提供适配板端的 OpenCV、NumPy 和 BPU 运行时。安装脚本会先验证 `cv2`、`numpy`、`PIL`、`yaml`，并把缺少 `cv2.aruco.DICT_APRILTAG_36h11` 视为安装错误；它不会擅自从公网下载。板端预检还会再次验证 `hbm_runtime`、`rclpy`、`sensor_msgs` 和 OpenCV 的 `tag36h11` 支持。

项目会优先通过板端现有 `setuptools/wheel` 离线安装；若仅打包工具版本不足，安装器退回到 release 内 `.pth` 启动方式，不下载依赖。两种方式最终都必须产生 `/opt/rdk-patrol/current/.venv/bin/rdk-patrol` 并通过预检。

若缺少依赖，请准备与板端架构和 Python 版本匹配的 wheelhouse，再在板端执行：

```bash
sudo bash scripts/rdk/install.sh \
  --source /path/to/RDK_S100_Patrol_Final \
  --wheelhouse /path/to/wheelhouse
```

不要用普通 x86 Windows wheel，也不要用会覆盖 RDK 厂商 OpenCV/BPU 库的通用包。

## 4. 手工部署

已将交付目录放到板端时：

```bash
cd /path/to/RDK_S100_Patrol_Final
sudo bash scripts/rdk/install.sh \
  --source "$PWD" \
  --prefix /opt/rdk-patrol \
  --data-dir /var/lib/rdk-patrol \
  --service-user sunrise
```

常用命令：

```bash
sudo systemctl status rdk-patrol --no-pager
sudo systemctl restart rdk-patrol
sudo systemctl stop rdk-patrol
journalctl -u rdk-patrol -f
sudo -u sunrise /opt/rdk-patrol/current/scripts/rdk/preflight.sh
```

服务实际执行：

```bash
rdk-patrol run \
  --config /opt/rdk-patrol/current/configs/system.yaml \
  --data-dir /var/lib/rdk-patrol
```

CLI 还提供：

```bash
rdk-patrol preflight --config ... --data-dir ...
rdk-patrol export-ledger --data-dir ... --output /path/to/报警台账.html
```

这三个命令是部署脚本依赖的正式运行契约。若 `preflight.sh` 提示入口不存在，说明交付包不完整，不应继续现场验收。

## 5. 目录和权限

```text
/opt/rdk-patrol/
  current -> releases/<当前版本>
  releases/<历史版本>

/var/lib/rdk-patrol/
  alarms/                 报警索引和关键帧，非 72 小时轮转对象
  recordings/raw/         原始双目组合视频
  recordings/annotated/   标注主视图视频
  review_queue/            MiniMax 待复核/重试队列
  outbox/                 未来钉钉发送预留队列（首版关闭）
  exports/                拉回包
  site-config/            system.yaml、双目标定和 AprilTag 点位登记
  state/                  运行状态
```

`/etc/rdk-patrol.env` 权限应为 `root:<服务用户组> 0640`。不要把它放入拉回包、工单截图或 Git。

## 6. 现场配置持久化

新部署会保留：

- `/var/lib/rdk-patrol/site-config/system.yaml`
- `/var/lib/rdk-patrol/site-config/stereo_gs130w.yaml`
- `/var/lib/rdk-patrol/site-config/points.yaml`

首次安装，或旧安装尚无 `site-config/system.yaml` 时，安装器会从当前新 release 初始化它；之后升级优先使用现场副本，不会覆盖已调好的夜间时间窗、阈值和录像参数。业务参数应修改持久副本，不要直接修改 `/opt/rdk-patrol/current/configs/system.yaml`。

完成业务参数调整、标定或点位登记后，应用并重启：

```bash
sudo /opt/rdk-patrol/current/scripts/rdk/apply-site-config.sh
```

它只把上述三个白名单文件应用到当前 release，不触碰密钥、报警和录像。修改前先备份；升级后必须运行预检，若新版本新增必填配置项，应在备份基础上人工合并并重新验收。

## 7. 局域网访问

浏览器打开：

```text
http://192.168.66.65:8081/
```

网页没有账号密码，是只读 GET 服务。仅允许在隔离、可信的巡检局域网开放 8081；不要直接映射到互联网。若系统启用了防火墙，只对运维网段放行：

```bash
sudo ufw allow from 192.168.66.0/24 to any port 8081 proto tcp
```

根据现场实际网段调整，不要照抄错误网段。

## 8. 升级和回退

升级再次执行部署脚本即可；旧 release 默认保留。回退前先列出真实目录：

```bash
ls -l /opt/rdk-patrol/releases
readlink -f /opt/rdk-patrol/current
```

确认目标后再人工切换并重启：

```bash
sudo ln -sfn /opt/rdk-patrol/releases/<已确认版本> /opt/rdk-patrol/current
sudo systemctl restart rdk-patrol
```

回退不会回退 `/var/lib/rdk-patrol/site-config` 和报警数据，其中 `system.yaml` 仍保持现场版本。切换后必须重新运行预检；若旧程序与当前现场配置结构不兼容，应恢复事先确认过的配置备份。

## 9. 启动门槛

以下任何一项失败，都不能标记为“生产可用”：

- HBM 模型或元数据缺失。
- 相机话题不存在、画面拆分错误或输入不足 15 FPS。
- 系统时间不同步。
- 数据盘容量不足或重启后未挂载。
- Python/ROS 2/BPU 运行时不可用。
- 完整链路实测不足 15 FPS。

双目标定无效时允许系统运行：明火仍正常报警，但距离标注为“不可用”。AprilTag 与视觉指纹都无法识别时，车辆/垃圾桶点位事件必须跳过，不能猜测点位。
